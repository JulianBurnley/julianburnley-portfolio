ARIA and Accessibility

Accessible Rich Internet Applications, commonly known as ARIA, is a standard created by the World Wide Web Consortium. ARIA provides additional information that helps assistive technologies understand the purpose, relationships, and current condition of elements on a webpage.

ARIA is especially useful when HTML, CSS, and JavaScript are used to build custom interactive components. It can improve the experience of people who use screen readers, keyboard navigation, and other assistive technologies.

ARIA should support semantic HTML rather than replace it. Native HTML elements should be used whenever they already provide the needed meaning and behavior.

ARIA concept categories

Roles

ARIA roles define the purpose of an element or region. They help assistive technologies determine whether an element functions as a landmark, widget, alert, dialog, or another type of component.

Abstract Roles
Abstract roles organize related ARIA roles and define characteristics shared by those roles.
  • input is a superclass for widgets that accept user input.
  • section is a superclass for structural containment roles.

Important: ARIA standards state that authors must not use abstract roles directly in web content.

Document Structure Roles
Document structure roles describe the organization and purpose of content on a page.
  • article identifies a self-contained section of content.
  • heading identifies a heading for a section.
Landmark Roles
Landmark roles identify major areas of a webpage.
  • banner identifies site-oriented introductory content.
  • navigation identifies a collection of navigational links.
Live Region Roles
Live-region roles identify areas whose content may change dynamically.
  • alert identifies important, time-sensitive information.
  • status identifies advisory information that does not require immediate attention.
Widget Roles
Widget roles identify interactive controls and components.
  • tab identifies a selectable item within a tab list.
  • searchbox identifies an input used to enter search criteria.
Window Roles
Window roles identify dialogs displayed within the main browser window.
  • dialog identifies a dialog or application window.
  • alertdialog identifies an urgent dialog that requires a response.

Properties

ARIA properties provide additional information about an element. They can describe its label, relationships, live-region behavior, or connection to another element. Properties usually change less often than states.

Widget Attributes
Widget properties describe interactive controls.
  • aria-errormessage identifies the element that contains an error message.
  • aria-haspopup indicates that an element can open a popup.
  • aria-label provides an accessible text label.
Live Region Attributes
Live-region properties control how dynamic updates are announced.
  • aria-live="off" means updates are not normally announced.
  • aria-live="polite" means updates are announced when they will not interrupt the user.
  • aria-live="assertive" means updates are announced immediately.
Drag-and-Drop Attributes
Earlier ARIA standards included attributes used to describe drag-and-drop behavior.
  • aria-dropeffect="copy" indicated that a copy would be created.
  • aria-dropeffect="move" indicated that an item would be moved.
  • aria-dropeffect="link" indicated that a reference would be created.

These drag-and-drop attributes are deprecated and should not be used in new projects.

Relationship Attributes
Relationship properties connect elements to one another.
  • aria-controls identifies an element controlled by the current element.
  • aria-labelledby identifies the element that labels the current element.
  • aria-describedby identifies the element that describes the current element.
ARIA Standards: Properties

States

ARIA states describe the current condition of an element. States are dynamic and may change when a user interacts with a component or when an application updates its content.

Widget States
Widget states describe the current condition of a control.
  • aria-checked="true" indicates that a checkbox, radio button, or similar widget is selected.
Live Region States
Live-region states indicate whether updated content is complete.
  • aria-busy="true" indicates that an element is still being updated.
Selection States
Selection states identify the currently selected item.
  • aria-selected="true" indicates that a tab, option, or similar item is selected.
Expansion States
Expansion states communicate whether controlled content is currently open or closed.
  • aria-expanded="false" indicates that controlled content is collapsed.
